# Onyema Miracle — Portfolio

Personal portfolio site for a brand + product designer: a home page with a
filterable work grid, an About page, and long-form case studies.

Built with **Next.js 16** (App Router), **React 19**, **TypeScript**,
**Tailwind CSS v4** and **Lenis** (smooth scroll). Designed in Figma and
translated component by component.

## Getting started

```bash
npm install
npm run dev      # http://localhost:3000
```

| Script | What it does |
| --- | --- |
| `npm run dev` | Starts the dev server (parses case studies first via `predev`) |
| `npm run build` | Production build (parses case studies first via `prebuild`) |
| `npm run start` | Serves the production build |
| `npm run lint` | Runs ESLint |
| `npm run parse-content` | Re-generates the case-study JSON from `content/` on demand |

## Project structure

```
content/                      Case-study source files (tagged plain text)
  README.md                   Full tag syntax reference — read before writing one
  <project-id>/<slug>.txt
scripts/                      Zero-dependency parser: .txt -> JSON
public/
  case-studies/<project-id>/  Images for each case study (.webp)
  about_page_assets/          About page icons
  credentials/                Certificate previews
  resume.pdf
src/
  app/                        Routes: /, /about, /work/[slug], 404, sitemap, robots, OG images
  components/                 UI components (Navbar, Grid, ProjectWidget, ...)
    case-study/               Block renderers used by case-study pages
  lib/
    data/projects.ts          Loads every case-study JSON at build time
    data/case-studies/        Generated JSON (committed; regenerated by the parser)
    site.ts                   Site-wide constants (name, email, site URL)
    types/caseStudy.ts        Block schema
```

Design decisions, Figma references and intentional deviations from the design
are documented in [`CLAUDE.md`](./CLAUDE.md).

## Adding or editing a case study

1. Write `content/<project-id>/<slug>.txt` using the syntax in
   [`content/README.md`](./content/README.md).
2. Put images in `public/case-studies/<project-id>/<slug>/`. Use `.webp`, and
   keep them under ~2400px wide (see **Images** below).
3. Run `npm run parse-content` (or just `npm run dev`) to regenerate
   `src/lib/data/case-studies/<project-id>/<slug>.json`, then commit both the
   `.txt` and the JSON.

The parser warns about any image path that doesn't exist under `public/`.

## Images

Export case-study images as WebP at no more than ~2400px wide (the layout
never displays them larger than ~1440 CSS px). Anything bigger only costs
load time.

## Environment

| Variable | Purpose |
| --- | --- |
| `NEXT_PUBLIC_SITE_URL` | Production origin (e.g. `https://example.com`). Used for `metadataBase`, the sitemap, `robots.txt` and Open Graph images. Falls back to Vercel's production domain, then `http://localhost:3000`. |

## Deployment

The site is a standard Next.js app and deploys to Vercel with no extra
configuration. Set `NEXT_PUBLIC_SITE_URL` in the project's environment
variables so link previews and the sitemap use the real domain.
